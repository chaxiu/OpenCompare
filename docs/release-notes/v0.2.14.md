# OpenCompare v0.2.14 release notes

English | [简体中文](./v0.2.14.zh-CN.md)

v0.2.13 was never published; its contents ship in this release. v0.2.14 wraps up two changes already merged into main plus one round of first-paint convergence. The structured semantic comparison location sync now falls back to the nearest common ancestor when one side adds or removes lines, and the default structured semantics gate matrix grows from 9 gates to 10. The top bar keeps only four permanent actions (New comparison / Open file / Open folder / Settings); the brand subtitle and the demo samples entry are gone, the scene segmented control is retired so the opened folder or file type decides the scene, sessions switch through session tabs, samples move to Samples & debugging in Settings, and the empty state keeps only the three real CTAs. The diff and merge algorithms, directory scanning, snapshot format and release channel are unchanged.

## What changed

### Top bar and entry points

- **Four permanent actions**: the top bar keeps only New comparison / Open file / Open folder / Settings. The demo samples button and its dropdown are removed, and so is the brand subtitle.
- **Scene follows the opened item**: the scene segmented control (view switch) is retired; the opened folder or file type decides the scene. Switching sessions moves to the session tab, which shows a type icon per scene, and the shell entry list goes from 20 to 18.
- **Samples & debugging**: Settings gains a Samples & debugging section that carries the five sample kinds (directory / code 3-way / CSV / JSON-YAML / remote snapshot) through the existing load paths. The directory workflow toolbar no longer carries the two demo entries.
- **Empty state keeps real paths**: the empty state keeps only the three real CTAs (New comparison / Open file / Open folder), and the hint points at Settings → Samples & debugging.

### P1 semantic location wrap-up

- **Ancestor fallback**: when a line exists on only one side, the missing side falls back to the nearest common ancestor line and adds the `opacity-60` weakened highlight instead of dropping the highlight.
- **Exact lines do not regress**: when an exact counterpart line exists, the highlight still lands on that line and never falls back to an ancestor.

### Structured semantics gate

- **Default matrix 9→10**: the default gate matrix grows from 9 gates to 10, covering structured / semantic (`structured` / `semantic`) comparison under the same gate posture.

## Not in this release

- No changes to the diff and merge algorithms: the four-state semantics, line diff results and three-way merge behavior are unchanged.
- No changes to directory scanning, the snapshot format or the release channel.
- No separate v0.2.13 release: that version was never published and its contents are part of this one.

## Risk and verification scope

The changes are limited to the top bar / first paint of the shell, the structured semantic view and the gate matrix; the diff / merge / scanning algorithms, file I/O and snapshot format are untouched. This release has no performance or memory measurement, so this file states no measured numbers.

## Upgrade

Upgrade from v0.2.12. Replace the app with the v0.2.14 package for your platform (macOS `.dmg` / `.zip`, Windows installer, Linux `.AppImage` / `.deb`). No data migration is needed; existing sessions and settings keep working. The signing posture is unchanged: the macOS build is Developer ID signed and Apple-notarized, and CI fails closed when credentials are missing.
