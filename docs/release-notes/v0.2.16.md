# OpenCompare v0.2.16 release notes

English | [简体中文](./v0.2.16.zh-CN.md)

v0.2.16 converges five user-visible directory and interface changes already merged into main: directory-only states now use the left-only / right-only vocabulary, template placement works on real user directories, a repeated dry-run recognises slots that are already placed, failure messages follow the interface language, and the built-in samples moved into Settings. The diff and merge algorithms, directory scanning, the snapshot format and the release channel are unchanged.

## What changed

### Directory-only states use the shared vocabulary

- **Right only / Left only**: directory comparison row badges, the directory toolbar legend and the shell status-bar legend reuse the filter-tab vocabulary, so an added row reads `Right only` and a removed row reads `Left only`. The text and code diff vocabulary (`Added` / `Removed`) stays unchanged, and the filters and the four-state counts keep the same meaning.

### Template placement on real user directories

- **Pick the roots first**: after choosing template placement in a directory session you pick the roots first. Template A reads only the current left root; for the scattered tree B you can set the root and the output root with the system directory picker, by dropping a directory or by typing a path (`~` expands), and an output root that does not exist yet is marked as to be created.
- **Dry-run reads the real output root**: the plan is built from the files and directories that already exist under the output root, and the preview writes nothing. Each of the four partitions lists its slots and sources, the default checks, the executable count and the confirm button read one resolved plan, and confirming writes only the checked rows.
- **Write and re-check**: every written file lands with the source `modifiedMs`, and each row is re-checked against the source sha256 and `mtimeSec`.

### Repeated dry-run is idempotent

- **Already placed**: when a file at the output root has the same content sha256 as its source, the row reads `Already placed` and shows no overwrite warning, stays unchecked by default and does not join the executable list; with nothing executable the confirm button is disabled. Changing the content returns the row to the conflict or overwrite protection.

### Failure messages follow the interface language

- **Localized failures keep the facts**: sync write refusals and refresh failures after a write map stable system codes to the Chinese and English dictionaries while keeping the target path and the OS code; template placement preflight refusals, per-row write failures and re-check failures follow the current interface language as well, so the English interface no longer shows Chinese sentences from the main process.

### Samples live in Settings

- **One sample entry**: the first screen and the directory toolbar no longer show built-in sample paths; the built-in samples, the remote snapshot example and the failure demo are all opened from `Settings → Samples & debugging`.

### Windows portable download

Windows ships both the NSIS installer and a portable `.zip` (extract and run, no installation step). Auto-update keeps resolving to the NSIS installer, so the portable zip is a download only.

## Not in this release

- No changes to the diff and merge algorithms: the four-state semantics, line diff results and three-way merge behavior are unchanged.
- No changes to directory scanning, the snapshot format or the release channel.
- The gate matrix, end-to-end fixtures and baseline documents stay on the verification side and are not new user features.

## Risk and verification scope

The changes are limited to directory status wording, template placement on real directories, the placed-slot check, localized failure messages and the sample entry; the diff / merge / scanning algorithms, the four-state counts and the snapshot format are untouched. This release states no performance or memory numbers.

## Upgrade

Upgrade from v0.2.15. Replace the app with the v0.2.16 package for your platform (macOS `.dmg` / `.zip`, Windows installer, Linux `.AppImage` / `.deb`). On Windows you can either install with the NSIS `.exe` or download `OpenCompare-0.2.16-win-x64.zip` and run it right after extracting; auto-update still only uses the NSIS `.exe`. No data migration is needed; existing sessions and settings keep working. The signing posture is unchanged: the macOS build is Developer ID signed and Apple-notarized, and CI fails closed when credentials are missing.
