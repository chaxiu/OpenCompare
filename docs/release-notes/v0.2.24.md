# OpenCompare v0.2.24 release notes

English | [简体中文](https://github.com/chaxiu/OpenCompare/blob/v0.2.24/docs/release-notes/v0.2.24.zh-CN.md)

v0.2.24 closes this feature iteration with three user-visible fixes and two coverage-governance changes: the window menu bar and toolbar now follow the app theme, the code toolbar exposes the swap entry with its shortcut, and previous / next diff navigation centres the target block; the coverage gate now exempts modules with 0 executable statements and the release-point coverage baseline was resampled. Comparison semantics, IPC, export and snapshot formats are untouched.

## What changed

### Menu bar and toolbar follow the theme

The native window menu bar and title backdrop now follow the same light or dark result as the in-app theme, and the self-drawn toolbar band uses the same surface level as the main window. The renderer pushes the theme mode rather than a resolved value, so "follow the system" keeps tracking the OS; the main process applies it through Electron's native theme capability and restores the same setting on the next launch. On macOS the global menu bar is owned by the OS and cannot be tinted by the app, which stays a known platform difference.

### Visible swap entry and shortcut

The code diff toolbar now shows "swap sides" directly instead of hiding it under the "more" menu. The toolbar button, the menu item and the `Cmd/Ctrl+Shift+S` shortcut all call the same swap action, and swapping again restores the original order; the shortcut string, tooltip and menu label come from one source, so they cannot drift apart.

### Centred previous and next jump

Previous and next now scroll the target block until it is centred vertically in the viewport and keep surrounding context rows visible; the old behaviour that pinned a block's first row to the top is gone. First block, last block, short documents, an unknown viewport height and a block taller than the viewport are all clamped deterministically to `[0, maxScroll]`, and the two panes share one computed target.

### Zero-statement modules are exempt

The coverage gate now treats modules whose executable totals for statements, lines, functions and branches are all zero as explicitly exempt: each exempt module is printed once with its `0 executable statements` basis, and it no longer trips the module set or the per-module branch floor. A module that does have executable code but zero coverage still fails, and the floors, ignore directives and exclude scope are unchanged.

### Release-point coverage resample

The release-point baseline was resampled once after v0.2.23 from a real v8 cold run, which refreshed `.munk/baseline/coverage.json` with its sampling commit and totals. The gate was also run both ways on that baseline, with the positive case passing and the negative floor and stale cases failing as expected. This is a validation-governance change, not a new user feature.

## Windows installer and portable zip

Windows keeps the same packaging contract as the previous release; see the portable download note below.

### Windows portable download

Windows ships both the NSIS installer and a portable `.zip` that runs right after extraction with no installation step. Auto-update keeps resolving to the NSIS installer, so the portable zip is a download only.

## macOS signing and notarization

The macOS build keeps Developer ID signing and Apple notarization, and CI fails closed when the signing credentials are missing. This release does not change that posture.

## Not in this release

- The **ignore whitespace** switch is still off by default, and when it is on only spaces and tabs are swallowed, with highlights and the difference count reading one comparison result while the status bar shows raw values.
- Reload still re-reads the current pair in the same session, so the scroll position and switches stay put, and an unreadable side keeps the previous result.
- The swap action still exchanges content, the ruler and counts and the status bar values, and swapping again restores the original order.
- No changes to export or snapshot formats, directory scanning, the release channel or comparison semantics.
- CI, coverage, test, screenshot provenance and ratchet work in this range is validation plumbing, not a user feature.

## Risk and verification scope

The new part of v0.2.24 relative to v0.2.23 is the theme sync for native window chrome and the toolbar band, the visible swap entry with its shared shortcut, the centred previous / next navigation, the explicit zero-statement exemption and the release-point resample. Comparison semantics, IPC, export and snapshot formats are untouched. Verification covers the theme mode bridge and surface layering in both themes, the three swap entry points sharing one action, the scroll clamping cases, the coverage exemption with positive and negative self-tests, the resampled baseline through the release gate, and the bilingual notes and screenshot provenance through the repository gates. This release states no performance or memory numbers.

## Upgrade

Upgrade from v0.2.23. Replace the app with the v0.2.24 package for your platform (macOS `.dmg` / `.zip`, Windows installer, Linux `.AppImage` / `.deb`). On Windows you can either install with the NSIS `.exe` or download `OpenCompare-0.2.24-win-x64.zip` and run it right after extracting; auto-update still only uses the NSIS `.exe`. No data migration is needed; existing sessions and settings keep working.
