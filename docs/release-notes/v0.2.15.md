# OpenCompare v0.2.15 release notes

English | [简体中文](./v0.2.15.zh-CN.md)

v0.2.15 converges three user-visible directory sync changes already merged into main: directory sync now lands links as links, the sync preview summary follows the checked deletions, and both READMEs spell out the three sync postures. The diff and merge algorithms, directory scanning's no-follow counting posture, the snapshot format and the release channel are unchanged.

## What changed

### Links are synced as links

- **Source-only links stay links**: a symbolic link that exists only on the source side is created as a link on the target side. Its target string is stored verbatim, so a relative path is never rewritten to an absolute one, a dangling link lands as a link, and a link that points at a directory lands as a link as well without entering the target subtree.
- **Replacing an ordinary file never writes through**: when a target-side ordinary file is replaced by the source link, only that entry is replaced; the file the old entry pointed at is left intact.
- **Mirror deletion removes the link only**: with a mirror delete checked, the run deletes the link itself and never reaches through it to the file it points at.
- **Link time alignment**: when both sides hold the same link and only the link time differs, the preview lists a link-time alignment and the run can align it without copying any content.

### Preview summary follows the checked deletions

- **One predicate for the summary**: the "this run" counts, the Apply button and the no-executable guidance come from the same decision. With mirror deletions unchecked the executable count is 0 and Apply is disabled; checking one item makes it 1 and enabled, and unchecking it returns to 0.
- **The delete group header counts both**: the mirror delete group header shows the planned count and the checked count together.
- **The reported deletions match the disk**: the count in the completion notice comes from the run's own execution record, so it matches what actually left the disk.

### README sync postures

- **Three postures in both READMEs**: incremental sync only adds and overwrites, never deletes; mirror sync also lists target-only items as pending deletions, which stay unchecked by default and run only when you check them; changes made outside the app are read on the next comparison, with no background file watcher.

## Not in this release

- No changes to the diff and merge algorithms: the four-state semantics, line diff results and three-way merge behavior are unchanged.
- No changes to the directory scanning no-follow posture, the snapshot format or the release channel.

## Risk and verification scope

The changes are limited to directory sync link handling, the sync preview summary and the two README feature lines; the diff / merge / scanning algorithms, the four-state counts and the snapshot format are untouched. This release states no performance or memory numbers.

## Upgrade

Upgrade from v0.2.14. Replace the app with the v0.2.15 package for your platform (macOS `.dmg` / `.zip`, Windows installer, Linux `.AppImage` / `.deb`). No data migration is needed; existing sessions and settings keep working. The signing posture is unchanged: the macOS build is Developer ID signed and Apple-notarized, and CI fails closed when credentials are missing.
