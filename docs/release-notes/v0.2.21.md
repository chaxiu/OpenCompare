# OpenCompare v0.2.21 release notes

English | [简体中文](https://github.com/chaxiu/OpenCompare/blob/v0.2.21/docs/release-notes/v0.2.21.zh-CN.md)

v0.2.21 converges the user-visible work already merged into main. It carries the comparison history and the three-way merge session entry that were tagged in v0.2.20 but never reached a public release, and it adds the visual polish round: a compact application chrome, a single-row directory toolbar that fits narrow windows, a quieter status bar with an accessible four-state legend, a tighter diff view and one shared design token source. Beyond this session and presentation work, comparison semantics, IPC, export and snapshot formats are untouched.

## What changed

### Comparison history

The history list is now a pure model persisted through the platform port, so the recent items survive a restart. The new page lists recent comparisons, and one click reopens the same file pair, directory pair or merge with its previous switches. Before a recorded path is reopened it is preflighted; a broken path is reported in place and no half-built tree is created. Failed entries stay as error rows that can be removed one by one, the list is capped at 20 mixed records and can be cleared explicitly.

### Three-way merge session

A real merge session can be opened from the workbench and from history. Reopening a merge keeps the left and right switches, and restarting the app restores the same session.

### Compact application chrome

The ready-state top control band is 120 logical pixels in total: the app title is 32, the session tabs 28, the context toolbar row 36 and the panel header 24. The status bar is a single 24-pixel row.

### Directory toolbar and narrow windows

The directory toolbar is one row: the filter segmented control, one solid primary action, a 12-pixel gap with a 1-pixel vertical divider, then the more menu. Six snapshot import and export actions, HTML export and local-path hiding moved into that more menu or settings.

The narrow-window fold ladder is fixed: the legend state words collapse first, then the primary sync label, then the row container wraps. A single row band is 36 and a wrapped band is 72, with no horizontal clipping.

The more menu stays fully visible inside an 800-pixel-tall viewport; when there is not enough room below it flips upward or is clamped to the viewport instead of hiding items behind an inner scrollbar. Escape and outside clicks still close it.

### Status bar and diff legend

The directory four-state legend lives only in the filter row and is no longer repeated in the status bar. The status bar keeps only the row or item metrics of the current scene and the encoding and line-ending facts, and when both sides share the same encoding and line ending they are written once.

On a narrow window the status bar wraps to a second row instead of clipping, and the single-row height is 24.

In the light theme the four-state legend foreground reaches at least 4.5 to 1 against the chip background, measured at 4.78, 4.66, 4.60 and 4.62; the dark values are unchanged at 6.41, 6.47, 5.16 and 6.51.

### Diff view

Code lines are 22 pixels tall, and diff body text is 12-pixel monospace with aligned line numbers. The right side has a 2-pixel indicator track with the current viewport rectangle, diff blocks and the hovered line number, kept 6 pixels clear of the vertical scrollbar. Word-level differences now use a 12 percent soft background with a 1-pixel underline instead of a 40 percent solid fill.

### Design tokens and controls

`src/renderer/src/assets/main.css` is the only token source: font sizes 11, 12, 13, 14 and 15, line heights 16, 18, 20 and 24, a 0.25rem spacing base of 4, 8, 12, 16 and 24, radii of 4, 6 and 8, and control heights of 28, 32 and 36. The light and dark themes redefine the same token names.

The control trio is a Button with three emphasis levels, a 28 by 16 square checkbox, a 20-pixel chip with an 8-pixel dot, a label and a 12 percent semantic background, and a 30-pixel tab with a 2-pixel brand underline. The interface settles on four hues: blue, green, red and amber. A conflict reuses the modified colour family and is separated by a dashed outline and wording, while danger shares its hue with removed.

### Documentation and screenshots

The two README screenshots were recaptured after the visual foundation and the toolbar model change, and the captured commit, byte sizes and sha256 provenance in `docs/screenshots.md` were repinned. The v1 visual before and after screenshots and the measurement document landed with the visual round. The README body and its version pointer are unchanged.

## Windows installer and portable zip

Windows keeps the same packaging contract as the previous release; see the portable download note below.

### Windows portable download

Windows ships both the NSIS installer and a portable `.zip` that runs right after extraction with no installation step. Auto-update keeps resolving to the NSIS installer, so the portable zip is a download only.

## macOS signing and notarization

The macOS build keeps Developer ID signing and Apple notarization, and CI fails closed when the signing credentials are missing. This release does not change that posture.

## Not in this release

- The **ignore whitespace** switch is still off by default, and when it is on only spaces and tabs are swallowed, with highlights and the difference count reading one comparison result while the status bar shows raw values.
- Reload still re-reads the current pair in the same session, so the scroll position and switches stay put, and an unreadable side keeps the previous result.
- The swap action still exchanges content, the ruler and counts and the status bar values, and swapping again restores the original order.
- No changes to export or snapshot formats, directory scanning, the release channel or comparison semantics beyond the presentation work above.
- CI, coverage and baseline document work in this range is validation plumbing, not a user feature.

## Risk and verification scope

This release is presentation only: the compact chrome, the directory toolbar band, the status bar and diff legend, the diff view metrics, the shared token source and the screenshots. Comparison semantics, IPC, export and snapshot formats are untouched. Verification covers the shell layout model, the toolbar fold ladder, the status bar metrics, the diff view geometry and the token contract through the repository gates. This release states no performance or memory numbers.

## Upgrade

Upgrade from v0.2.20. Replace the app with the v0.2.21 package for your platform (macOS `.dmg` / `.zip`, Windows installer, Linux `.AppImage` / `.deb`). On Windows you can either install with the NSIS `.exe` or download `OpenCompare-0.2.21-win-x64.zip` and run it right after extracting; auto-update still only uses the NSIS `.exe`. No data migration is needed; existing sessions and settings keep working.
