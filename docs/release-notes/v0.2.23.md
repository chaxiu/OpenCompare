# OpenCompare v0.2.23 release notes

English | [简体中文](https://github.com/chaxiu/OpenCompare/blob/v0.2.23/docs/release-notes/v0.2.23.zh-CN.md)

v0.2.23 converges the user-visible work already merged into main: files with an unknown extension now open by their content, the README screenshots cover both languages with the capture language pinned by settings, the code view highlights a fixed set of extensions in both panes, and oversized files fall back to plain text at a stated character boundary. Comparison semantics, IPC, export and snapshot formats are untouched.

## What changed

### Unknown extensions open by content

When the extension cannot be identified, the open path reads the raw bytes of each side once and decides between text and binary. Text opens in the code family with the same UTF-8 or GBK encoding and newline facts as any other text file; binary is rejected with a message that names the side and the file, and the message states that the extension is checked by content and binary files are not supported.

The same decision runs at every open entry: manual paths plus argv and `opencompare://` links, drag and drop with the file picker and history reopen, directory tree double-click, and the three-way merge. Known extensions keep their previous behaviour and add no read at all; an unknown extension reads each side exactly once, and the text, encoding, newline and byte facts come from that single read.

### Bilingual README screenshots

The README now carries four screenshots: the workbench and the file diff, each in English and Chinese. All four were captured from the real built application against real temporary trees, and the language is pinned by the persisted settings file rather than the host locale. The captured commit, byte sizes and sha256 provenance in `docs/screenshots.md` were repinned to that capture.

### Syntax highlighting

Both diff panes now colour code through one entry, `resolveSyntaxView`, and fall back to plain text whenever it returns `null`. The V1 language map covers explicit extensions only: `ts`, `tsx`, `js`, `jsx`, `mjs`, `cjs`, `py`, `json`, `jsonc`, `yml`, `yaml`, `md`, `css`, `html`, `htm`, `xml`, `sh` and `bash`. Files outside that map keep the previous plain-text rendering, so nothing new is guessed from content.

Token colours and diff colours are layered by `overlay`, so syntax foreground and diff semantic backgrounds and underlines coexist in the same line. Additions, removals, modifications and conflicts keep their existing semantics; highlighting changes only how the code itself is coloured.

### Large-file fallback

Highlighting stops at `SYNTAX_MAX_HIGHLIGHT_CHARS = 262_144`, counted after CRLF is folded to LF. A side whose folded length is at or below the threshold is highlighted, and a side one character past it falls back to plain text before it reaches the syntax cache or the tokenizer. The fallback is a stated behaviour boundary, not a degradation mode: the plain path keeps the same rows, counts, markers and diff semantics.

## Windows installer and portable zip

Windows keeps the same packaging contract as the previous release; see the portable download note below.

### Windows portable download

Windows ships both the NSIS installer and a portable `.zip` that runs right after extraction with no installation step. Auto-update keeps resolving to the NSIS installer, so the portable zip is a download only.

## macOS signing and notarization

The macOS build keeps Developer ID signing and Apple notarization, and CI fails closed when the signing credentials are missing. This release does not change that posture.

## Not in this release

- The **ignore whitespace** switch is still off by default, and when it is on only spaces and tabs are swallowed, with highlights and the difference count reading one comparison result while the status bar shows raw values.
- Reload still re-reads the current pair in the same session, so the scroll position and switches stay put, and an unreadable side keeps the previous result.
- The swap action still exchanges content, the ruler and counts and the status bar values, and swapping again restores the original order.
- Syntax highlighting adds no new comparison semantics: the extension map is explicit, unknown extensions stay plain text, and no language is inferred from content.
- No changes to export or snapshot formats, directory scanning, the release channel or comparison semantics beyond the content fallback above.
- CI, coverage, test, screenshot provenance and ratchet work in this range is validation plumbing, not a user feature.

## Risk and verification scope

The new part of v0.2.23 relative to v0.2.21 is the content-based fallback decision at open, the screenshot assets, the V1 syntax overlay and the large-file fallback boundary. Comparison semantics, IPC, export and snapshot formats are untouched. Verification covers the content-family decision and its read budget, the four open entry points, the extension map and the token/diff overlay in both panes, the exact threshold boundary through the large-file gate, and the bilingual notes and screenshot provenance through the repository gates. This release states no performance or memory numbers.

## Upgrade

Upgrade from v0.2.21. Replace the app with the v0.2.23 package for your platform (macOS `.dmg` / `.zip`, Windows installer, Linux `.AppImage` / `.deb`). On Windows you can either install with the NSIS `.exe` or download `OpenCompare-0.2.23-win-x64.zip` and run it right after extracting; auto-update still only uses the NSIS `.exe`. No data migration is needed; existing sessions and settings keep working.
