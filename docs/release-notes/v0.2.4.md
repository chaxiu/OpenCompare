# OpenCompare v0.2.4 发布说明

OpenCompare v0.2.4 是 v0.2.3 的正式承接版本。**本版包含 v0.2.3 已合入但未发布的改动：悬空链接容错、摘要缓存改进。** v0.2.3 从未打 tag、从未公开 Release，其用户可见内容全部并入本版，安装本版即可得到这部分改动。

同批合入目录对比在大目录下的可用性修复：主进程流式哈希、批量分页扫描、进度与取消、窗口化目录树、弹窗遮挡与相位计数。

## 本次修复

### 悬空链接容错（v0.2.3 并入）

- 目录列举、扫描、对比与快照构建遇到悬空符号链接或不可读项时跳过并计数，不再让整次目录对比失败。
- 工作台就地以 info 提示「已跳过 N 个不可读项/悬空链接」，目录视图同时给出跳过计数，跳过项不进入对比结果。

### 1. 内容摘要改由主进程流式哈希

- 文件内容摘要由主进程按流读取并做 SHA-256 流式字节哈希，不再逐文件把正文拉回渲染进程后再算摘要。
- DawnChat ↔ ZenMind 实测 134 万文件的目录对比，原实现需读 10.67 GiB 正文；本版对比只保留每份文件的摘要（摘要直写缓存）。

### 2. 目录扫描改批量、分页 + 有界并发

- 目录列举改为批量、分页请求：一次 IPC 覆盖多个目录，按页推进。
- 条目元数据查询共用一份有界并发预算，批量目录数不再放大在飞句柄数；真实工程目录对比不再因句柄耗尽中断。

### 3. 扫描 / 哈希显示进度并可取消

- 扫描目录与校验内容（哈希）阶段都有实时进度计数，界面显示当前阶段与已处理量。
- 任意时刻可点「取消」：进行中的读取流被销毁，本次对比不提交半成品结果，工作台保持取消前状态，后续对比不受影响。

### 4. 目录结果树窗口化

- 目录结果树改为窗口化（虚拟滚动）渲染，只绘制可视区域内的行。
- 150 万行规模的目录树，尾部依然可达；滚动与展开不再因为一次性渲染整棵树而失去响应。

### 5. 「新建对比」弹窗不再遮挡进度

- 从主入口「新建对比」弹窗发起目录对比时，弹窗在扫描开始前关闭。
- 进度条与取消按钮全程可见、可点，不再被弹窗遮罩覆盖。

### 6. 相位计数不归零

- 扫描目录段报已扫描的文件数，校验内容段报已校验的文件数。
- 每段内计数单调递增；从扫描切到校验不归零、不回退，读数不会倒退。

## 已知问题

以下三项**已知未修**，这里写清影响面，请勿当作已修复：

1. **同进程连续多轮大目录对比内存增长（已知未修）**：同一进程内连续做多轮大目录对比时，主进程常驻内存会逐步抬升，实测 849 → 1,510 MB。全程未 OOM，对比结果正确，重启应用后回落。影响面：长时间连续对比超大目录的用户会看到内存占用偏高。
2. **取消时 stderr 出现 `ECANCELED` 日志噪声（已知未修）**：取消目录对比时，主进程 stderr 会打印 `ECANCELED` 相关日志。它只是日志噪声，不影响取消结果——对比确实停止、不提交半成品，也不影响后续对比。
3. **符号链接计数放大（已知未修）**：含悬空符号链接的目录，`已跳过` 计数按扫描侧累加，同一条链接在左右两侧各计一次，显示值可能大于实际跳过的条目数。影响面：提示数字偏大，不影响对比结果与会话内容。

## 升级建议

建议 **v0.2.2 及更早** 的用户升级到 v0.2.4，尤其是经常对比真实工程目录或大目录的用户——旧版本遇到悬空符号链接 / 不可读项会让整次目录对比失败，超大目录还会因为逐文件回传正文与整树渲染而变慢甚至失去响应。

下载 v0.2.4 对应平台的新安装包覆盖安装即可：

- macOS：`.dmg` 或 `.zip`
- Windows：`OpenCompare.Setup.0.2.4.exe`
- Linux：`.AppImage` 或 `.deb`

macOS 安装包经 Developer ID 签名 + Apple 公证流程产出；签名与公证口径与上一版一致，凭据缺失时发版流程会直接失败（fail-closed），不会发布未签名裸包。

## 关于上一个版本

v0.2.2 修复的是大目录对比的文件句柄耗尽（`EMFILE` / `ENFILE`）：目录内容读取、快照内容读取与目录条目遍历改为默认 **8 路有界并发**，句柄耗尽时工作台给出可读提示而不是崩溃。该修复在本版保持有效，本版未改动并发默认值。

`v0.1.2` 的 tag 与已发布资产保持原样，不删除、不移动、不重打、不替换；v0.2.1 与 v0.2.2 的发布说明保留为历史记录。v0.2.3 从未发布，不保留独立的发布说明。
