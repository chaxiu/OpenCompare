# OpenCompare v0.2.25 release notes

English | [简体中文](https://github.com/chaxiu/OpenCompare/blob/v0.2.25/docs/release-notes/v0.2.25.zh-CN.md)

v0.2.25 adds spreadsheet comparison for `.xlsx` / `.xlsm` workbooks and fixes two blockers found after v0.2.24: workbooks now open in the sandboxed renderer build, and a second launch that takes over with a file argument no longer offers the app directory as the left side. Comparison semantics for the existing text, code, directory and CSV families, IPC, export and snapshot formats are untouched.

## What changed

### Workbook value extraction

A new pure layer reads `.xlsx` / `.xlsm` workbooks into the same `{ header, rows, meta }` shape the CSV path already uses, so table alignment needs no second conversion. Only cached formula results are read: no formula is evaluated, and a cell without a cached value compares as empty while the count is reported in `meta`. Merged ranges contribute only their top-left anchor, styles and comments never take part in the diff, and dates normalise against the workbook's own 1900 or 1904 basis. Hidden rows and columns stay in the comparison by default and are annotated in `meta`, empty headers fall back to column letters, and several sheets pair by name case-insensitively with the side-only sheets listed separately. The vendored SheetJS 0.20.3 tarball is pinned by sha256 and the npm 0.18.5 line is never used.

### Parse limits and zip-bomb rejection

Workbook reads are bounded before anything is inflated: the zip central directory is checked for container size, entry count, largest entry, compression ratio and a cumulative decompression budget, so a container that would inflate far past its stored size is rejected as a zip bomb. Sheet XML, the shared-string table and sheet bounds carry their own limits, and a runtime watermark records a warning at 60% of the budget and aborts at 80%. Every rejection raises one `XLSX_LIMIT_EXCEEDED` error carrying `{ limit, observed }`, produces no rows and leaves no session state behind.

### Workbook pairs in the workbench

Dropping two `.xlsx` / `.xlsm` files now opens the same four-state comparison as CSV, with per-cell highlights and per-sheet counts. Merged anchors, the 1900 / 1904 date bases and the hidden-row and hidden-column annotations all come from the parse metadata, so the ignore-hidden toggle recomputes the table without re-reading the file. The two sides parse strictly in order, left before right, and an over-limit pair is rejected with the comparison-limit message before a tab is created.

### Workbooks open in the shipped renderer

The shipped build parses bundles in a sandboxed renderer that has no `Buffer` or `process` global, so workbook opens failed there while passing in the test environment. The parse layer no longer touches either global, and a static guard in the suite fails if they come back.

### Second launch honours the file argument

A second launch hands its arguments to the running instance. When the first launch recorded the app entry as `.` and the takeover spelled it absolutely, that argument survived as the left side and the app directory was offered as a comparison input. Both spellings of the app entry are now stripped through one normaliser before the takeover's working directory is used as the base.

## Windows installer and portable zip

Windows keeps the same packaging contract as the previous release; see the portable download note below.

### Windows portable download

Windows ships both the NSIS installer and a portable `.zip` that runs right after extraction with no installation step. Auto-update keeps resolving to the NSIS installer, so the portable zip is a download only.

## macOS signing and notarization

The macOS build keeps Developer ID signing and Apple notarization, and CI fails closed when the signing credentials are missing. This release does not change that posture.

## Not in this release

- The **ignore whitespace** switch is still off by default, and when it is on only spaces and tabs are swallowed, with highlights and the difference count reading one comparison result while the status bar shows raw values.
- Reload still re-reads the current pair in the same session, so the scroll position and switches stay put, and an unreadable side keeps the previous result.
- The swap action still exchanges content, the ruler and counts and the status bar values, and swapping again restores the original order.
- Workbook comparison stays read-only over data: formulas are never evaluated, `.xls` / `.xlsb` files are still refused, and export or snapshot formats, directory scanning and the release channel are unchanged.
- The coverage, test, screenshot provenance and ratchet work in this range is validation plumbing, not a user feature.

## Risk and verification scope

The new part of v0.2.25 relative to v0.2.24 is the workbook value extraction, the parse-limit and zip-bomb rejection layer, the four-state workbook pair in the workbench, and the two fixes for the sandboxed renderer and the second-launch argument. Comparison semantics for the existing families, IPC, export and snapshot formats are untouched. Verification covers the parse semantics, the pinned dependency integrity, the limit and zip-bomb rejections with their error shape, the per-sheet four-state counts, the hidden-row and hidden-column policy, the renderer global guard, the launch takeover argument, and the bilingual notes through the repository gates. This release states no performance or memory numbers.

## Upgrade

Upgrade from v0.2.24. Replace the app with the v0.2.25 package for your platform (macOS `.dmg` / `.zip`, Windows installer, Linux `.AppImage` / `.deb`). On Windows you can either install with the NSIS `.exe` or download `OpenCompare-0.2.25-win-x64.zip` and run it right after extracting; auto-update still only uses the NSIS `.exe`. No data migration is needed; existing sessions and settings keep working.
