# OpenCompare v0.2.5 发布说明

OpenCompare v0.2.5 收口大目录反复对比的三处退化：同进程连续多轮对比的内存收敛、取消时的日志噪声、符号链接的计数口径。本版不新增功能，对比结果与快照格式保持不变。

## 本次修复

### 1. 同进程连续多轮大目录对比内存收敛

- 内容摘要缓存改为**有界缓存**：按条目数与估算字节双重设限，超出上限按最近最少使用淘汰；关闭或替换目录会话时显式释放该会话根下的条目，不再依赖垃圾回收时机。
- 不可见会话不再构建或保留整份行模型，测量路径每轮开始前释放上一轮会话。
- 真实 DawnChat ↔ ZenMind（不跟随符号链接口径下约 75 万文件）同一应用进程连续 3 轮实测：renderer 峰值 `1,257,750,528` B，修复前基线为 `1,960,394,752` B；第 3 轮相对第 2 轮的 renderer 增量 `71,286,784` B，进入增量阈值内，不再逐轮线性抬升。
- 数字与判定全部来自归档证据 `docs/perf/evidence/dawnchat-zenmind-20261022-post-fix-3rounds.json`，说明见 `docs/perf/large-directory-memory.md`。

### 2. 取消是干净的结构化结果

- 取消通过**结构化取消**返回值贯穿平台边界：不再把取消异常抛到 IPC handler 外，界面显示已取消并保留取消前的会话与结果。
- 取消后不提交半棵树、不写半份缓存、不残留读取流，可立即再次发起对比。
- 主进程 stderr 对一次取消实测零 `Error occurred in handler`、零 `OperationCancelledError`、零 `ECANCELED`；扫描阶段与哈希阶段各覆盖一次，由 `pnpm test:cancel` 门禁持续断言。

### 3. 符号链接口径：不跟随符号链接

- 目录扫描**不跟随符号链接**：不进入链接指向的任何目录，链接自身作为一条叶条目参与 `same / added / removed / modified`；链接目标子树不产生任何条目，也不计入文件数与四态计数。
- 悬空链接不再是跳过项，它的目标串照常参与比较；只有 EACCES / ELOOP 等真正不可读的条目或目录被跳过，并按扫描侧分列为**已跳过：左 X / 右 Y**，不再输出含义模糊的合并总数。
- 真实两目录 footer 条目总数由跟随口径的 1,338,294 降到 752,479，四态计数之和与 `fileCount` 相等；新旧对照与四态表见 `docs/symlink-no-follow.md`。
- 下钻规则：指向**文件**的链接可读取目标内容，指向**目录**的链接只是叶条目；快照线格式 `opencompare.snapshot/v1` 不变，链接条目按上述语义记录。

## 已知问题

本版没有遗留未修条目。上一版记录的多轮内存增长、取消日志噪声、符号链接计数三项均已在本版按实测修复并保留证据；若发现新的可复现问题，请附命令与原始输出提交 Issue。

## 升级方式

建议 **v0.2.4 及更早** 的用户升级到 v0.2.5，尤其是需要反复对比真实大目录的用户。

下载 v0.2.5 对应平台的新安装包覆盖安装即可：

- macOS：`.dmg` 或 `.zip`
- Windows：`OpenCompare-Setup-0.2.5.exe`
- Linux：`.AppImage` 或 `.deb`

macOS 安装包经 Developer ID 签名 + Apple 公证流程产出；签名与公证口径与上一版一致，凭据缺失时发版流程会直接失败（fail-closed），不会发布未签名裸包。

## 关于上一个版本

v0.2.4 承接 v0.2.3 已合入但未发布的悬空链接容错与摘要缓存改进，并合入目录对比的批量扫描、进度与取消、窗口化目录树等修复；v0.2.4 的 tag 与已发布资产保持原样，不删除、不移动、不重打、不替换。v0.2.3 从未发布，不保留独立的发布说明。
