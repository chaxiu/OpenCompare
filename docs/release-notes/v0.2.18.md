# OpenCompare v0.2.18 release notes

English | [简体中文](https://github.com/chaxiu/OpenCompare/blob/v0.2.18/docs/release-notes/v0.2.18.zh-CN.md)

v0.2.18 converges the text-comparison normalization already merged into main: code and text comparison gain two switches that are on by default — ignore newline differences and ignore encoding differences. The diff and merge algorithms, directory scanning, the snapshot format, exported content and the release channel are unchanged.

## What changed

### Two comparison switches, on by default

- **Ignore newline differences**: with the switch on, lines that differ only in line-ending style are not counted in line-level highlights, inline highlights or the difference count; turning it off restores a strict byte-for-byte comparison. The count in the status bar and the count in the results read one comparison result, so they never disagree.
- **Ignore encoding differences**: with the switch on, files whose text is identical but whose bytes differ only by encoding show no line-level or inline highlights and do not add to the difference count; switching it off compares byte-for-byte. Line-level highlights, inline highlights and the count all follow that same rule.

### Status bar and raw probe values

- **Raw values on both sides**: the status bar always shows the newline style and encoding detected on each side — `Left newline`, `Left encoding`, `Right newline` and `Right encoding` — and switching either comparison switch never rewrites those values.
- **Probe travels with the session**: opening a pair of files carries the probe facts for both sides into the session, which is why the status bar has values without an extra scan.
- **No write-back**: normalization only changes the comparison result; the original files are not written back, and exported content, the directory four-state counts, the snapshot format and the three-way merge are untouched.

## Windows installer and portable zip

Earlier CI injected the macOS Developer ID signing credentials (`CSC_LINK` / `CSC_KEY_PASSWORD`) into every target of the three-platform matrix, so the Windows build carried a signature Windows does not trust and `Get-AuthenticodeSignature` reported the v0.2.17 `OpenCompare-Setup-0.2.17.exe` as `UnknownError`. The injection is now narrowed to the macOS target, so from this version on the Windows installer is back to its normal unsigned posture (`NotSigned`); SmartScreen still warns about an unknown publisher, and signing is added once a Windows code-signing certificate is available. The v0.2.17 Windows installer carries that invalid signature, so use v0.2.18 directly.

### Windows portable download

Windows ships both the NSIS installer and a portable `.zip` that runs right after extraction with no installation step. Auto-update keeps resolving to the NSIS installer, so the portable zip is a download only.

## macOS signing and notarization

The macOS build is Developer ID signed and Apple-notarized, and CI fails closed when the signing credentials are missing. This release narrows the signing credentials to the macOS target only, so the Windows build is no longer signed with them; macOS Developer ID signing and Apple notarization themselves are unchanged.

## Not in this release

- No changes to the diff and merge algorithms beyond the two switches: the four-state semantics, line diff results and three-way merge behavior are unchanged.
- No changes to directory scanning, the snapshot format, exported content or the release channel.

## Risk and verification scope

The change is limited to the two normalization switches, the raw newline and encoding read-out in the status bar, and the single shared difference count; the diff and merge algorithms, directory scanning and the snapshot format are untouched. Real on-disk evidence covers six variants — UTF-8, UTF-8 BOM, UTF-16LE and GBK crossed with LF and CRLF — in both a thousand-line group and a 5 MiB group. This release states no performance or memory numbers.

## Upgrade

Upgrade from v0.2.17. Replace the app with the v0.2.18 package for your platform (macOS `.dmg` / `.zip`, Windows installer, Linux `.AppImage` / `.deb`). On Windows you can either install with the NSIS `.exe` or download `OpenCompare-0.2.18-win-x64.zip` and run it right after extracting; auto-update still only uses the NSIS `.exe`. No data migration is needed; existing sessions and settings keep working. The signing posture is unchanged: the macOS build is Developer ID signed and Apple-notarized, and CI fails closed when credentials are missing.
