## 6. 更新元数据：AppImage blockmap 形态

结论（记录，不改写已发布资产）：

- electron-builder 把 AppImage 的 blockmap payload **内嵌在 AppImage 文件尾部**，不产出独立的 `*.AppImage.blockmap` 资产；`latest-linux.yml` 的 `blockMapSize` 是该内嵌 payload 的长度。
- 因此 v0.2.4 的 `latest-linux.yml`（`blockMapSize: 126886`，无独立 AppImage blockmap 资产）形态自洽，不需要补发 `*.AppImage.blockmap`。
- 本仓库新增本地可验断言：`release/*.AppImage` 末 4 字节按小端 uint32 解码后必须等于 `latest-linux.yml` 中该 AppImage 条目的 `blockMapSize`，不等即失败；该断言不要求存在独立 `*.AppImage.blockmap` 资产。

## 7. 遗留缺陷：Windows 更新 URL 与真实资产名不一致

来源：本机复核（case 记录）＋ `evidence/win-job.log` 构建日志。

| 项 | 内容 |
| --- | --- |
| 等级 | P2（不阻塞本次发布） |
| 现象 | `latest.yml` 的 Windows `files[].url` 写 `OpenCompare-Setup-0.2.4.exe`（实测 HTTP 404），真实资产是 `OpenCompare.Setup.0.2.4.exe`（HTTP 200） |
| 根因 | `nsis` 段未设 `artifactName`，磁盘产物名含空格 `OpenCompare Setup 0.2.4.exe`；GitHub 上传时空格被规范化成点，而元数据模板是连字符 |
| 起始版本 | v0.2.2 起既有（v0.2.2 的 `latest.yml` 同样写连字符名，资产为点号名），不是 v0.2.4 引入 |
| 运行时影响 | 无运行时消费者：`electron-updater` 不在依赖与锁文件中，`src/` 无 `autoUpdater` 引用，应用未实现自动更新；仅将来接自动更新时 Windows 会拉不到包 |
| 本次处置 | 只修未来：`electron-builder.yml` 显式 `nsis.artifactName: '${productName}-Setup-${version}.${ext}'`，finalize 新增「`latest*.yml` 的 `files[].url` 必须命中该 Release 资产名」的 fail-closed 门。**不重发、不改写、不重传** v0.2.4 及更早的任何已公开资产与 tag |
