# 多会话标签切换/关闭与未保存提示

本项是「OpenCompare 生产级可用与合规发布」五步主链路的第 4 步：**会话成为可真管理的对象**——标签可切换、可关闭，含未保存修改的会话关闭前先提示，全程不需要刷新页面或重启应用脱困。

现状证据（已核对仓库）：
- `SessionTabs`（`src/renderer/src/components/SessionTabs.tsx`）只有 `onSelect`，**没有任何关闭入口**，也没有未保存标记；`SessionTab` 类型只有 id/title/subtitle/icon。
- `Workbench.tsx` 用 `sessions` + `activeId` 管理会话，`renderScene(active)` **只挂载当前活动会话**；切走即卸载 `CodeView`，其 `leftText`/`rightText` 本地工作副本随之丢失，而 `session.dirty` 由 `handleSessionDirty` 镜像后**不会**被卸载清理 → 切走再切回会出现「内容回到磁盘原文、脏标记仍为 true」的矛盾状态。
- 前序已交付会话级 `dirty`（`WorkbenchSession#dirty`，由 adhoc 文件对会话的 `CodeView.onDirtyChange` 上报）以及每侧原位保存 / 重置 / 只读拒绝语义；**尚未消费该标记做事关闭提示**。
- `load()`（样本加载）走 `setSessions(loaded)` **整表替换**，会抹掉已打开的真实会话（前序交付摘要已点名留给本项）；失败分支 `setSessions([])` 同样会清空。
- 关闭最后一个会话后若无兜底，`status` 仍为 `ready`、`activeId` 悬空 → 工作区空白，属「断头路」。

## 范围

1. **标签切换**：点击任一标签即切换活动会话，工作区内容、状态栏会话标识与统计随活动会话更新；标签顺序不变。
2. **标签关闭入口**：每个标签提供独立的关闭按钮（可访问名称区分会话，如「关闭 <会话标题>」），点击关闭按钮**不等于**切换标签；无未保存修改的会话关闭直接生效，不弹确认。
3. **关闭后的活动会话落点**：关闭当前活动会话且仍有其他会话 → 自动激活相邻会话（优先后继，无后继则前一个），工作区不出现空白；关闭非活动会话 → 当前活动会话与内容不变。
4. **关闭最后一个会话 → 回到空首屏**：标签栏隐藏、空态「打开文件 / 打开文件夹」CTA 可见，随后打开新会话正常工作；全程无刷新 / 重启。
5. **未保存提示**：`session.dirty === true` 的会话被关闭时，先弹出确认（复用既有 `Dialog`），提示包含该会话标题与「未保存修改」语义，并提供两个动作：「继续编辑」（取消关闭）与「放弃修改并关闭」。
   - 「继续编辑」→ 会话保留、未保存内容保留、标签未保存标记仍在，无错误提示。
   - 「放弃修改并关闭」→ 会话被移除；若为活动会话按第 3 条规则落点。
6. **标签未保存标记**：dirty 会话的标签上有可见的未保存标记（`title`/`aria` 可读），保存或重置清除 dirty 后标记消失。
7. **切换不丢未保存内容**：从 A 切换到 B 再切回 A，A 的未保存工作文本与「已修改（未保存）」呈现、标签未保存标记三者保持一致（不得静默丢弃修改，也不得出现「提示有修改但内容已是原文」的假提示）。
8. **样本加载不再抹掉真实会话**：已有会话时加载演示样本按会话 id upsert/合并，不整表替换，真实会话与其顺序保持不变；样本加载失败且有会话时保留现有会话并报错（无会话时仍显示既有「样本库读取失败」错误态 + 重试）。
9. **关闭来源目录会话不产生断头**：目录下钻出来的文件会话在所依赖的目录会话被关闭后仍能正常显示；「返回上级目录视图」有可用目录会话则切换过去，没有则给出明确提示，不出现空白或需刷新。
10. **壳层状态清理**：关闭会话时一并清理该会话的目录树状态 / 滚动等壳层缓存，避免残留状态被后续同名会话误用。

## 验收

- ac-tabs-switch: 点击任一标签后该会话变为活动会话，工作区渲染其内容、状态栏「会话」值随之更新，标签列表与顺序不变。
- ac-tab-close-clean: 关闭无未保存修改的会话时立即移除该标签、不弹确认；若关闭的是非活动会话，当前活动会话及其工作区内容不变。
- ac-close-active-neighbor: 关闭当前活动会话且仍有其他会话时，自动激活其相邻会话（优先后继，无后继取前一个），工作区立即显示该会话内容，不出现空白工作区。
- ac-close-last-empty: 关闭最后一个会话后回到空首屏（「打开文件」「打开文件夹」可见、标签栏不渲染），且随后可正常打开新会话，全程无刷新 / 重启。
- ac-close-dirty-prompt: 关闭 `dirty` 为 true 的会话时先出现确认提示，提示含该会话标题与「未保存修改」语义，并提供「继续编辑」「放弃修改并关闭」两个动作；此时会话尚未被移除。
- ac-close-dirty-cancel: 在未保存提示中点「继续编辑」，会话保留、其未保存内容与「已修改（未保存）」呈现保留、标签未保存标记仍在，且不出现错误提示。
- ac-close-dirty-discard: 在未保存提示中点「放弃修改并关闭」，该会话从标签栏移除；若它是活动会话，按 ac-close-active-neighbor 规则激活相邻会话。
- ac-dirty-marker-on-tab: 存在未保存修改的会话标签上有可读的未保存标记（`title` 或等价可访问文本）；保存或重置清除 dirty 后该标记消失。
- ac-switch-keeps-edits: 在会话 A 覆写差异块产生未保存修改后切到 B 再切回 A，A 的修改后工作文本与「已修改（未保存）」标记仍在，标签未保存标记与之一致；随后关闭 A 会触发未保存提示。
- ac-no-stale-dirty: 已保存或已重置的会话（dirty 为 false）关闭时直接关闭、不弹提示，标签也不再显示未保存标记。
- ac-samples-load-keeps-sessions: 已有真实会话时加载演示样本，真实会话标签仍在且顺序不变（活动会话不被切走），样本会话按 id 合并且不产生重复标签；样本加载失败且有会话时保留现有会话并给出错误提示。
- ac-close-parent-no-deadend: 关闭目录下钻文件会话的来源目录会话后，该文件会话仍正常显示；点「返回上级目录视图」时有可用目录会话则切换过去，否则给出明确提示，均不出现空白视图或需刷新。
- ac-gates: `pnpm typecheck` / `pnpm lint` / `pnpm test` 在改动后全绿（含随标签结构变化的既有断言更新与新用例）。
- ac-self-test-desktop: 在真实 Electron 窗口（`pnpm dev`）+ 真实文件系统走通：打开多个真实会话 → 来回切换 → 关闭无修改会话（直接生效）→ 在含未保存修改的会话上关闭（先出提示，「继续编辑」保留 / 「放弃修改并关闭」移除）→ 全程不用刷新或重启脱困。

## 非目标

- 不做「保存并关闭」第三分支，也不做关闭前自动保存：提示只给「继续编辑」与「放弃修改并关闭」，需要保存时由用户先取消、在视图内按既有每侧保存动作写回。
- 不做批量关闭（关闭全部 / 关闭其他 / 全部关闭）、不做标签拖拽重排、不做标签右键菜单与「标签溢出更多」菜单（沿用现有横向滚动）。
- 不做快捷键（`Cmd+W` / `Ctrl+W` 等）与会话恢复 / 崩溃恢复 / 最近打开列表 / 会话持久化。
- 不做自由文本编辑器，不改 `CodeView` 的覆写 / 重置 / 保存 / 只读拒绝语义与 dirty 判定本身，也不改视图内「已修改（未保存）」的呈现方式。
- 不改目录对比 / 代码 Diff / 3-way / CSV / 结构化算法内核，不改快照导入导出、目录同步与模板归位的预览确认语义。
- 不新增状态管理库 / 路由 / 全局 context；不新建模态或提示体系（确认复用 `Dialog`，错误提示沿用既有 `report` + 状态栏语气）。
- 不改视觉 token 与组件库体系（`SessionTabs` 只新增关闭按钮与未保存标记，一律引用现有 token）。
- 不做样本库加载失败态的重设计；不做 Web 与 Electron 行为分叉。
- 不改 `.munk/baseline/**`（由 Delivery 折入）。

## 实现约束

- 会话增删与活动会话落点的唯一来源是 `Workbench` 的 `sessions` / `activeId`；任何时刻 `activeId` 必须指向现存会话或 `null`（为 `null` 时渲染空首屏，而不是空白工作区）。
- `SessionTabs` 保持受控组件：新增关闭回调与未保存标记入参；关闭按钮点击不得同时触发标签切换（独立可访问名称，如「关闭 <会话标题>」）。
- 未保存判定的唯一依据是 `WorkbenchSession#dirty`（由文件视图 `onDirtyChange` 上报）；壳层不得自行推断「有修改」，也不得缓存在视图里的临时副本上判断。
- 切换标签不得销毁会话内未保存的工作缓冲区，确保 dirty 与视图实际内容始终一致（不得出现静默丢修改或空提示）。
- 关闭确认复用 `components/Dialog.tsx`，按钮走既有 `ToolbarButton`/`Button` 变体；文案语气与既有 `report(message, tone)` 一致，不写死颜色/尺寸。
- 关闭会话时清理该会话的壳层缓存（`directoryStates` / `directoryScroll` 等按会话 id 的条目），关闭后不残留可被复用会话误用的状态。
- 样本加载从整表替换改为按会话 id upsert/合并；失败时若已有会话则保留并报错，无会话时保持既有错误态。
- 学习前序交叠经验：`session.ts` / `Workbench.tsx` / `App.*.test.tsx` 是多个 WI 反复触碰的文件，改动后必须重跑 `pnpm typecheck` / `pnpm lint` / `pnpm test`。
- 平台缝不变：renderer 不得直接 import Electron；Web 内存实现保持可用（组件测试用内存 `PlatformPort`），不写只在 Electron 生效的分支。
- 单测按 `.agents/skills/vitest/SKILL.md`，React/RTL 用例沿用 `App.test.tsx` 的 `scriptedPort` 模式并随动 `App.snapshot.test.tsx`。
- **自测通道**：本项有可点的交互验收，`needSelfTest=true`；须在真实 Electron 窗口（`pnpm dev`）用真实文件完成，Web 通道自测不能替代关点。
