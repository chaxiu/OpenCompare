# Domain: perf-memory

性能测量与容量上限域：为大目录多轮对比提供**可复现的内存测量入口**（`pnpm perf:dir`）与**自动上限门**（`pnpm perf:gate`）。本域只做「测量 + 判定 + 证据落盘 + 门禁接线」，**不改任何内存行为**——缓存上限 / 淘汰、会话释放、行模型懒构建归 `memory-bounded`；符号链接计数口径归 `symlink-policy`；取消行为归 `cancel-structured`；目录对比语义与四态归 `directory`。本域是被测路径的观察者，不是对比引擎的改造者。

## 范围

- **测量入口（`pnpm perf:dir`）**：`scripts/perf-dir.mjs` 先 `electron-vite build`，再启动**真实 Electron 应用**（真实主进程 + 真实 renderer）并透传 `--left/--right`（均可重复、按出现顺序配对）、`--mode <upsert|multisession>`、`--rounds N`、`--settle <ms>`、`--out <file>`。轮次编排在渲染进程（`src/renderer/src/perf/PerfRunner.tsx` + `runRounds.ts`），走与 UI 同一条目录对比路径（`scanDirectory` → `compareDirectories` → `platform.digestFiles` → `createDirectorySession` → `commitUpsert`），并**渲染与工作台相同的 `SessionTabs` + `DirectoryView`（含 `TreeView` 虚拟列表与 `buildDirectoryRowModel`）**，使 fiber props、virtualizer 闭包与行模型进入被测面。会话列表语义取自 `workbench/sessionStore.ts`（`upsertSessions` / `replaceSessions` / `commitUpsert`），与 `Workbench.upsertSession` / `replaceSession` 逐字同义；**运行期不存在「轮次开始前释放上一轮会话」的路径**（旧 `onReleaseSession` / `held` 槽已删除）。`upsert` 模式复用同一对根、tab 恒 1、`sessionId` 恒定（等价真实 UI 的「重新对比同一对」）；`multisession` 模式逐轮追加不同根、tab 依次 1→2→3。N 轮在**同一应用实例 / 同一 renderer 进程**内连续完成；采样与证据落盘在主进程（`src/main/perf/harness.ts`、`evidenceFile.ts`），两者经仅测量模式启用的受控通道（`src/shared/perf/types.ts` 的 `PerfBridge`、`channels.ts` 白名单）同步轮次边界与 hold / settle 事件。
- **激活条件（零行为变化）**：只有 `--perf-harness` 与 `OPENCOMPARE_PERF=1` **同时存在**才进入测量模式（`src/shared/perf/args.ts` 的 `isPerfHarnessActive`，可单测断言）；普通启动与普通 `--left/--right` 对比不采样、不写任何证据文件。
- **参数解析与校验（`src/shared/perf/args.ts`）**：必填 `--left` / `--right` / `--out`；可选 `--mode`（`upsert` / `multisession`，默认 `upsert`，旧命令行不带该参数仍按 `upsert` 解释）、`--rounds`（默认 `DEFAULT_PERF_ROUNDS = 3`；`multisession` 下必须等于根对数，否则按对数取值）、`--settle`（默认 `DEFAULT_PERF_SETTLE_MS = 20000`，上限 `MAX_PERF_SETTLE_MS = 60000`，`0` 仅单测使用）、`--interval`（默认 `DEFAULT_PERF_INTERVAL_MS = 1000`，上限 `MAX_PERF_INTERVAL_MS = 2000`）、`--profile`（`real` / `gate`，默认 `real`）、`--fail-on-violation`。缺必填、未知参数、`--mode` 非法值、`--left`/`--right` 数量不一致、`upsert` 给多对 / `multisession` 只给一对、`--rounds` 非正整数、`--settle` 为负或超上限、根不存在或不可读时非零退出，stderr 指明具体违规参数或根路径，且不遗留标记为成功的证据文件。
- **RSS 采样口径（`src/shared/perf/rss.ts`，纯函数）**：`aggregateProcessRss(metrics)` 从主进程真实进程指标（`app.getAppMetrics()` 的 `workingSetSize` / `peakWorkingSetSize`）聚合：`renderer` = `type === 'Tab'` 进程中 RSS 最大者，`main` = `Browser` 主进程，`appTotal` = 所有上报进程 `workingSetSize` 之和；KB → bytes 在采样层转换。禁止用 renderer JS heap 估算或 mock 数值；采样值缺失或为 0 记 `invalid-sample`。
- **采样点（`src/shared/perf/recorder.ts`）**：`startup`（启动基线）、`boundary`（`round-<n>-start` / `round-<n>-end`）、`pre-round`（每轮扫描前）、`post-round`（每轮新树已上屏后）、`periodic`（按 `sampling.intervalMs` 的周期采样，默认 1s）、`settle`（末轮后等待 `--settle` 毫秒并强制 GC 的单次读数）。每轮至少各 1 条 `pre-round` / `post-round`，轮次边界成对出现；某轮周期采样条数覆盖 `floor(wallMs / interval) - 1` 以上。`peaks` 只聚合 ready / round / periodic，**排除 `settle`**，静置值单独成列（`settle` / `settleAt`）。
- **结构持有登记（`src/shared/perf/liveness.ts` + `PerfRunner` + `src/main/index.ts`）**：perf 模式在 app ready 前装 `--js-flags=--expose-gc`（普通启动绝不加），renderer 每轮结束与最终 settle 后连续 `gc()` 两次再经 `WeakRef` 登记表数 `DirectoryComparison` / `DirectoryRowModel`，以 `perf.event({type:'hold'})` 上报 `label / round / tabs / comparisons / rowModels / gc`；`gc` 不可用即 `hold-unmeasured` 违例（宁可红，不静默绿）。`DirectoryView` 的行模型 `useMemo` 与 `createDirectorySession` 只在测量开启时登记（关闭时零开销）。
- **真实哈希计数（`src/core/directory/compare.ts` + `src/renderer/src/workbench/snapshotOps.ts`）**：`counts.hashedFiles` / `counts.bytesToHash` 来自该轮 `platform.digestFiles` **实际成功哈希**调用累计（可选统计钩子，不改变对比结果 / 四态 / `counts` / 快照格式）；命中缓存而零哈希的轮次如实记 0。
- **阈值判定单点实现（`src/shared/perf/verdict.ts` + `perf/profiles.json`）**：档位上限集中在 `perf/profiles.json`（`real` / `gate` 两档），判定函数 `evaluatePerf` 两档共用：renderer ready 峰值、app 总峰值、末轮 settle renderer 上限（`settleRendererBytes`：`real` 1,363,148,800 B / `gate` 1,073,741,824 B）、第 3 轮相对第 2 轮 renderer 增量 `Δ3 ≤ min(100 MiB, max(30% × Δ1, 25 MiB))`（比例项下限保护 25 MiB，**仅 `upsert` 模式生效**）。实际生效阈值写入 `verdict.appliedThresholds.appliedRoundDeltaBytes`；任一违反或结构断言失败 → `verdict.ok=false` 且 `violations` 列出 `renderer-peak` / `renderer-round-peak` / `renderer-settle` / `settle-missing` / `app-total-peak` / `round-delta` / `hold-comparisons` / `hold-row-models` / `hold-tabs` / `hold-unmeasured` / `invalid-sample` / `harness-error`。档位只允许为覆盖真实持有而新增 / 收紧（本轮新增 `settleRendererBytes`），不得为变绿放宽既有上限。WI `wi_intake_aea03632d00a47e8` 再追加 `hot-round-hashed` / `hot-round-growth` / `settle-growth` / `reclaim-missing` / `reclaim-renderer` / `renderer-restart` 与非致命 `notices[]`（`renderer-peak-over-target` / `renderer-round-peak-over-target`）。
- **多 tab 持有形态：瞬峰护栏 vs 用户可见硬线（WI `wi_intake_aea03632d00a47e8`）**：`PerfMode` 增 `retained`（group3：同一实例建 3 tab 并保留 1→2→3 → `--hot-rounds` 轮活动 tab 热 upsert（默认 2）→ 关活动 tab 并让落点 tab 走热缓存重建），`--hot-rounds` 仅 `retained` 可用，`upsert` / `multisession` 拒绝该参数；`multisession` 仍 1→2→3 且轮界不删会话。证据加法字段 `settleStages[{label,rss,at,tabs}]`（`after-3-tabs` / `after-hot-upserts`）与 `reclaim{tabs,rss,at}`，`rounds[].rendererPid` 断言进程未重启。判定：多 tab 场景（`multisession` / `retained`）的瞬时 ready 峰值只作回归护栏 `TRANSIENT_PEAK_GUARDRAIL_BYTES = 2_415_919_104`（2.25 GiB），超过 profile 目标但未越护栏只写 `notices[]`、不判红；`settle` / `settleStages`（阶段间抬升 ≤ 100 MiB）/ `appTotal` / `reclaim`（≤ `RECLAIM_RENDERER_BYTES = 1_153_433_600`，关 1 tab 后 `tabs = pairs − 1`）/ 热轮 `hashedFiles = 0` / `hold` 结构（`comparisons === 1` 仅活动、`tabs` 按场景）仍是硬线。`upsert` 模式的 profile 峰值硬线不变。`perf/profiles.json` 六项数值零改动。
- **退出码（`resolvePerfExitCode` / `formatPerfViolations`）**：带 `--fail-on-violation` 且违规时非零退出，证据仍完整写出；`invalid-sample` 无论是否带该开关都非零退出。
- **证据文件（`src/shared/perf/types.ts` + `src/main/perf/evidenceFile.ts`）**：单个 JSON（`schema: opencompare.perf.directory/v1`，本轮为加法扩展——字段只增不改），**原子写**（同目录临时文件 + `rename`），单次 < 5 MB。字段：`generatedAt` / `appPid` / `commit{sha,dirty}` / `mode` / `pairs[]` / `roots{left,right}`（第一对，兼容旧字段） / `profile` / `sampling.intervalMs` / `sampling.settleMs` / `memoryDefinition` / `counts{files,dirs,hashedFiles,bytesToHash}` / `rounds[{index,startedAt,endedAt,wallMs,sessionId,tabs,counts,rendererRss,roundPeak,appTotalRss,rendererPid}]` / `totalWallMs` / `env{os,arch,cpuModel,cpuCount,totalMemBytes,node,electron}`（运行期真实探针，非常量）/ `samples[{label,phase,round,at,rss,pids}]` / `peaks{renderer,main,appTotal}`（不含 settle） / `settle` / `settleAt` / `holds[{label,round,tabs,comparisons,rowModels,gc}]` / `roundDeltas[]` / `verdict{ok,violations[],appliedThresholds}` / 失败时的 `error`。运行失败（renderer 崩溃、窗口提前关闭、超时）仍写带 `error` 且 `verdict.ok=false` 的部分证据并退出非零。
- **门禁命令（`pnpm perf:gate`，`scripts/perf-gate.mjs`）**：在系统临时目录生成**真实落盘**数据集（每侧 6,000 文件、总内容 ≥ 100 MiB、`d0/…/d4` 五层嵌套、每 50 个文件一处同大小不同内容、左右各含指向文件 / 目录 / 悬空目标的符号链接，并额外造 `links/left` 目录符号链接作为第三对根），同一数据集跑**三次** harness（`gate` 档、`--settle 5000`、超时 300 s）：① `upsert` 1 对根 5 轮，断言 tab 恒 1、`sessionId` 恒定、每轮 hold `comparisons=1` / `rowModels≤2` / `gc=true`、逐轮 `roundPeak` 与 `settle` 在档内、第 1 轮 `hashedFiles>0` 且第 2–5 轮 `hashedFiles=0`；② `multisession` 3 对根各 1 轮，断言 tab 依次 1/2/3、每轮 hold `comparisons=1`（仅活动 tab 持树）、`rowModels≤2`、`gc=true`、第 3 轮（`links/left` 别名轮）`hashedFiles=0`、逐轮峰值 ≤ 2.25 GiB 护栏、`peaks.appTotal` ≤ 2 GiB 门禁档；③ `retained` 3 对根 + 2 轮热 upsert，断言 tabs `1/2/3/3/3`、hold 序列 `round-1..3 / after-3-tabs / round-4..5 / after-hot-upserts / reclaim` 的 tabs 为 `1/2/3/3/3/3/3/2` 且 comparisons 恒 1、热轮 `hashedFiles=0`、两条 `settleStages` 的 tabs 为 3 且阶段抬升 ≤100 MiB、`reclaim.tabs=2` 且 renderer ≤ 1,100 MiB、`appTotal` ≤ 2 GiB、`rendererPid` 唯一。三份证据都要求「周期采样条数 ≥ floor(wallMs/interval)−1」「`roots` 指向本次临时目录」「非样本路径」。违规或断言失败即非零退出并输出被违反的阈值 / 结构 id。门禁被打包为 `.munk/code-gates.json` 的单一 argv `pnpm perf:gate`（无 `&&` / `|`），单次有界（`RUN_TIMEOUT_MS = 300_000`，目标 ≤ 3 分钟），运行结束即清理数据集；`PERF_GATE_EVIDENCE_DIR=<仓库外目录>` 只额外复制证据，不改变判定与退出码。
- **文档与真实取证（`docs/perf/`）**：`docs/perf/large-directory-memory.md` 给出 DawnChat↔ZenMind 的可复制命令（含 `--mode` / `--settle`）、产物路径、证据字段与口径、两种持有模式、结构断言、两档阈值与判定规则，并把 **ready 峰值** 与 **+settle 静置** 分列；§5 写死历史盲区（旧 harness「每轮释放会话 + 不渲染视图」不等于真实 UI 持有）与本次修复（视图 key 释放）及实测数字。`docs/perf/evidence/` 保存真实两目录（非内置样本）实跑证据，不提交生成的数据集。
- **公开发布包只读诊断（v0.2.6，`docs/perf/upsert-memory-diagnosis-2026-10-23.md`）**：对**已发布的公开包**（dmg sha256 锁定、非仓库内构建）做 `pnpm perf:dir` 之外的第二类取证——不起 harness，而是用 CDP 驱动已安装 app 的真实 UI 路径，只读测量两种场景：① 同一会话 upsert 反复对比 5 轮（`directorySessionId` 由两端根路径生成，重复即 upsert）；② 干净启动 `SKIP_A=1` 下 3 个不同根路径会话并发（tab 1→2→3，不关会话）。驱动脚本复用上一场复验的**只读原文件**（`repeat.mjs` / `multisession.mjs` / `lib.mjs`，运行前后 sha256 不变，不修改不另存），逐轮字段由同一实例上的**只读侧采样器**补齐（browser WS + `Target.attachToTarget(flatten:true)`，1 s 轮询 `Memory.getDOMCounters` / `performance.memory.usedJSHeapSize,jsHeapSizeLimit`（不可得时退 `Performance.getMetrics` 并注明口径）/ renderer 内 `ComparisonCache.stats`（`misses` 逐轮增量即该轮 `hashedFiles`），不占原脚本 page WS）。ready 峰值与 +20 s 静置收敛值**必须分列**，并按字节与 renderer 1,610,612,736 B / 静置 1,363,148,800 B / app 总 2,684,354,560 B 三个阈值比较。**仓库外**留证：≥3 份 `*.heapsnapshot`（组①第 1、2 轮 ready + 组② 3 tab ready，可选 settle），每份记录快照前 `JSHeapUsedSize`（含未回收垃圾）与快照后 reachable live 的差值，并回答 ready 时上一轮 `DirectoryComparison.root`、`DirectoryView` 的 `DirectoryRowModel`、`ComparisonCache.hashes` 条目是否仍可达（可达给 retainer path，不可达给“未持有”证据），同时量化 `estimatedBytes` 与实际 retained size 的差距以判断 128 MiB 估算是否漏算渲染侧。诊断产物**只写一份仓库文档**，`src/`、`package.json`、`.munk/code-gates.json`、README / CHANGELOG / `electron-builder.yml` / `docs/release*` 一律不动，不打包、不 push、不打 tag。

## 验收

- **ac-single-command-evidence**：给定两个存在可读的真实目录与 `--rounds N --out <file>`，一条命令跑完 N 轮并以退出码 0 写出证据 JSON；证据文件可被 schema 校验读取，`rounds.length === N`。
- **ac-cli-validation**：缺少 `--left`/`--right`/`--out`、未知参数、`--mode` 非法值、`--left`/`--right` 数量不一致、`upsert` 给多对 / `multisession` 只给一对、`--rounds` 为 0/负数/非数字、`--settle` 为负或超上限、根不存在或不可读时以非零退出，stderr 指明具体违规参数或根路径，且不遗留标记为成功的证据文件；不带 `--mode` / `--settle` 的旧命令行仍解析为 `upsert` / 20000 ms。
- **ac-evidence-schema**：证据含必填字段且类型正确：`commit{sha,dirty}`、`mode`、`pairs[]`、`roots{left,right}`、`counts{files,dirs,hashedFiles,bytesToHash}`、`rounds[{index,startedAt,endedAt,wallMs,sessionId,tabs}]`、`totalWallMs`、`env{os,cpuModel,cpuCount,totalMemBytes,node,electron}`、`samples[{label,phase,round,at,rss{renderer,main,appTotal}}]`、`peaks{renderer,main,appTotal}`、`settle`/`settleAt`、`holds[{label,round,tabs,comparisons,rowModels,gc}]`、`roundDeltas`、`verdict{ok,violations[],appliedThresholds}`；`peaks` 不含 settle 采样。
- **ac-env-probes-real**：`env` 各值与运行期真实探针一致（`os.release/arch`、`os.cpus()` 的型号与数量、`os.totalmem()`、`process.versions.node`、`process.versions.electron`），不是常量或手填。
- **ac-sample-points**：每轮至少产出 `phase=pre-round` 与 `phase=post-round` 各 1 条采样，轮次边界各 1 条（label 可区分），运行期间按固定间隔（≤2s，间隔写入证据）周期采样；某轮 `wallMs` 对应周期采样条数 ≥ floor(wallMs/interval) − 1；末轮结束后有一条 `phase=settle` 采样，等待时长等于 `--settle` 并写入 `sampling.settleMs`。
- **ac-app-total-rss**：`appTotal` = 主进程 + 所有 renderer/utility 进程 `workingSetSize` 之和（KB→byte），`renderer` = `type` 为 Tab 的进程中 RSS 最大者，`main` = 主进程；聚合函数对给定 metrics 数组有单测覆盖，口径字符串写入证据 `memoryDefinition`。
- **ac-same-process-rounds**：所有轮次在同一应用实例内完成，证据记录的 `appPid` 唯一且各轮 renderer pid 相同。
- **ac-harness-hold-modes**：harness 支持 `upsert` / `multisession` / `retained` 三种持有模式；`upsert` 每轮复用同一 `sessionId`（`directory:<left> ↔ <right>`，tab 恒 1、列表里只有最新会话对象），`multisession` 逐轮追加使 tab 依次 1→2→3，`retained` 建 3 tab 后保留并按 `--hot-rounds` 做活动 tab 热 upsert、最后关活动 tab 并重建落点 tab；证据 JSON 记录 `mode` / `pairs` / `rounds[].tabs` / `settleStages` / `reclaim`；运行期**不存在**「轮次开始前释放上一轮会话」的路径（`runRounds` hooks 无 `onReleaseSession`，源码与证据双证）。
- **ac-structural-single-hold**：perf 模式强制 GC 后的只读存活登记（`holds[]`）在 `upsert` 同实例 5 轮后报告 `comparisons=1`、`rowModels≤2`、`tabs=1`（含 settle 读数）；`multisession` / `retained` 场景每轮 `comparisons=1`（仅活动 tab 持树）、`tabs` 按场景 1/2/3（retained 再 3/3）、`rowModels≤2`，`retained` 的 `reclaim` 读数 `tabs=pairs−1=2`。`gc=false` 或 `holds` 缺失记 `hold-unmeasured` 红，不允许静默跳过。
- **ac-gate-red-on-old-behavior**：新增门禁断言在「旧行为」（人为保留旧会话 / 不清引用 / 无视图 key）下必须失败；交付给出可复现命令或单测用例（`perfShell.test.tsx` 的无 key 对照渲染断言旧 comparison / 旧行模型仍可达；`verdict.test.ts` 断言 `comparisons>1` / `rowModels>2` / `gc=false` 必红），证明门禁不是恒绿。
- **ac-gate-covers-upsert-and-multisession**：`pnpm perf:gate` 单次运行即覆盖 `upsert` 5 轮、`multisession` 3 会话与 `retained` 3 tab + 2 轮热 upsert，三份证据各给峰值、settle / settleStages / reclaim、holds 结构断言结果；退出码在违例时为非零。
- **ac-real-ui-upsert-peak**：打包 app + 原样 `repeat.mjs` 同会话 upsert 5 轮，第 1–5 轮 renderer ready 峰值逐轮 ≤ 1,610,612,736 B，不得出现第 3 轮及以后 >1536 MiB 的轮次。
- **ac-real-ui-upsert-settle**：同一 5 轮每轮 +20 s 静置 renderer ≤ 1,363,148,800 B，末轮再静置 30 s 后仍 ≤ 1,363,148,800 B。

- 不做 UI 变更：不加内存图表、设置项或新页面；证据是文件不是界面。
- 不引入性能测试框架、云压测、遥测上传或后台守护进程。
- 不得用内置 fixtures / samples 替代真实目录；不得手填、估算或从发布说明抄数字。
- 不为让门禁变绿而放宽阈值或缩小数据集；阈值调整必须能在证据里解释。
- 不改快照线格式、对比算法与四态定义；不改历史发布证据。
- 不为覆盖真实持有之外的目的放宽任何既有阈值或缩小数据集；本轮只新增 `settleRendererBytes` 与结构断言，`rendererPeakBytes` / `appTotalPeakBytes` / `roundDeltaMaxBytes` 一概不动；阈值调整必须能在证据里解释。

## 实现约束

- **入口形态单一**：复用现有 `electron-vite` 主 / 渲染构建，`pnpm perf:dir` 启动真实 Electron 应用；轮次编排在渲染进程（走 UI 同一条对比、会话提交与视图渲染路径），采样与证据落盘在主进程，两者经一个仅测量模式启用的受控通道同步轮次边界与 hold / settle。不另开第二套 harness。
- **harness 持有语义 = 真实 UI**：harness 渲染真实 `SessionTabs` + `DirectoryView`，会话列表只用 `workbench/sessionStore.ts` 的共享纯函数；不得存在「轮次开始前释放上一轮会话」的钩子，也不得用「每轮换 session id」规避 upsert 语义。
- **强制 GC 可失败不可跳过**：`--expose-gc` 只在 perf 模式安装；`gc` 不可用即 `hold-unmeasured` 红，不得静默跳过结构断言。
- **默认零行为变化**：harness 仅由显式 CLI 参数 + 环境变量（`--perf-harness` + `OPENCOMPARE_PERF=1`）激活；激活判断可被单测断言。
- **RSS 必须真实**：来自主进程 `app.getAppMetrics()` 的 `workingSetSize` / `peakWorkingSetSize`（必要时 `process.getProcessMemoryInfo()`）；禁止 renderer JS heap 估算或 mock 数值。采样值缺失或为 0 视为该轮 invalid，退出非零。
- **哈希计数落在真实调用上**：允许在 `@core/directory/compare` 增加可选统计回调 / 返回值，但不得改变对比结果、四态、`counts`、快照格式与既有测试语义。
- **阈值单点**：判定函数单点实现（`src/shared/perf/verdict.ts`），真实档与门禁档共用；档位上限集中在 `perf/profiles.json`，不在多处硬编码。新增 `settleRendererBytes` 与结构断言也走同一 `evaluatePerf`，`resolvePerfExitCode` / `formatPerfViolations` 不变。
- **证据原子写**：临时文件 + `rename`；运行失败也写出带 `error` 与 `verdict.ok=false` 的部分证据并退出非零；证据单次 < 5 MB，不提交生成的数据集。
- **周期采样**：默认 1s，可经参数覆盖（上限 2000ms）并写入证据。
