# Domain: perf-memory

性能测量与容量上限域：为大目录多轮对比提供**可复现的内存测量入口**（`pnpm perf:dir`）与**自动上限门**（`pnpm perf:gate`）。本域只做「测量 + 判定 + 证据落盘 + 门禁接线」，**不改任何内存行为**——缓存上限 / 淘汰、会话释放、行模型懒构建归 `memory-bounded`；符号链接口径归 `symlink-semantics`；取消行为归 `io-concurrency`；目录对比语义与四态归 `directory`；门禁清单形状与分层纪律归 `quality-gates`。

## 范围

- **测量入口（`pnpm perf:dir`）**：`scripts/perf-dir.mjs` 先 `electron-vite build`，再启动**真实 Electron 应用**（真实主进程 + renderer），透传 `--left/--right`（可重复、按序配对）、`--mode <upsert|multisession|retained>`、`--rounds N`、`--hot-rounds N`（仅 `retained`）、`--settle <ms>`、`--out <file>`。轮次编排在渲染进程（`src/renderer/src/perf/PerfRunner.tsx` + `runRounds.ts`），走与 UI 同一条对比路径（`scanDirectory` → `compareDirectories` → `platform.digestFiles` → `createDirectorySession` → `commitUpsert`），并渲染真实 `SessionTabs` + `DirectoryView`（含 `TreeView` 虚拟列表与 `buildDirectoryRowModel`），使 fiber props、virtualizer 闭包与行模型进入被测面。会话列表语义取自 `workbench/sessionStore.ts`（`upsertSessions` / `replaceSessions` / `commitUpsert`），与 `Workbench` 逐字同义；**运行期不存在「轮次开始前释放上一轮会话」的路径**。`upsert` 复用同一对根、tab 恒 1、`sessionId` 恒定；`multisession` 逐轮追加不同根、tab 1→2→3；`retained` 建 3 tab 保留后做活动 tab 热 upsert、最后关活动 tab 落到相邻已驻留 tab。N 轮在同一应用实例 / 同一 renderer 进程内完成；采样与证据落盘在主进程（`src/main/perf/harness.ts`、`evidenceFile.ts`），经仅测量模式启用的受控通道（`src/shared/perf/types.ts` 的 `PerfBridge`、`channels.ts` 白名单）同步轮次边界与 hold / settle 事件。
- **激活条件（零行为变化）**：只有 `--perf-harness` 与 `OPENCOMPARE_PERF=1` **同时存在**才进入测量模式（`src/shared/perf/args.ts` 的 `isPerfHarnessActive`，可单测）；普通启动与普通 `--left/--right` 对比不采样、不写证据。
- **参数解析与校验（`src/shared/perf/args.ts`）**：必填 `--left` / `--right` / `--out`；`--mode` 默认 `upsert`、`--rounds` 默认 `DEFAULT_PERF_ROUNDS = 3`（`multisession` 下必须等于根对数）、`--settle` 默认 `DEFAULT_PERF_SETTLE_MS = 20000`（上限 `MAX_PERF_SETTLE_MS = 60000`，`0` 仅单测）、`--interval` 默认 `DEFAULT_PERF_INTERVAL_MS = 1000`（上限 `MAX_PERF_INTERVAL_MS = 2000`）、`--profile real|gate`、`--fail-on-violation`。缺必填 / 未知参数 / 非法 mode / 左右数量不一致 / 模式与根对数不符 / `--rounds` 非正整数 / `--settle` 为负或超限 / 根不存在时非零退出，stderr 指明违规参数或根路径，且不留标记为成功的证据文件。
- **RSS 采样口径（`src/shared/perf/rss.ts`，纯函数）**：`aggregateProcessRss(metrics)` 从主进程真实进程指标（`app.getAppMetrics()` 的 `workingSetSize` / `peakWorkingSetSize`）聚合——`renderer` = `type === 'Tab'` 中 RSS 最大者，`main` = `Browser` 主进程，`appTotal` = 所有上报进程之和；KB→bytes 在采样层转换。禁止用 renderer JS heap 估算或 mock 数值；缺失或为 0 记 `invalid-sample`。
- **采样点（`src/shared/perf/recorder.ts`）**：`startup` / `boundary`（`round-<n>-start|end`）/ `pre-round` / `post-round`（新树已上屏）/ `periodic`（默认 1 s）/ `settle`（末轮后等待 `--settle` 并强制 GC 的单次读数）。每轮至少各 1 条 pre / post，边界成对；周期采样条数覆盖 `floor(wallMs / interval) - 1` 以上；`peaks` 只聚合 ready / round / periodic，**排除 settle**，静置值单独成列（`settle` / `settleAt`）。
- **结构持有登记（`src/shared/perf/liveness.ts` + `PerfRunner` + `src/main/index.ts`）**：perf 模式在 app ready 前装 `--js-flags=--expose-gc`（普通启动绝不加），renderer 每轮结束与最终 settle 后连续 `gc()` 两次，再经 `WeakRef` 登记表数 `DirectoryComparison` / `DirectoryRowModel`，以 `perf.event({type:'hold'})` 上报 `label / round / tabs / comparisons / rowModels / gc`；`gc` 不可用即 `hold-unmeasured` 违例（宁可红，不静默绿）；测量关闭时零开销。
- **真实哈希计数**：`counts.hashedFiles` / `counts.bytesToHash` 来自该轮 `platform.digestFiles` 实际成功哈希调用累计（可选统计钩子，不改变对比结果 / 四态 / `counts` / 快照格式）；命中缓存零哈希的轮次如实记 0。
- **阈值判定单点（`src/shared/perf/verdict.ts` + `perf/profiles.json`）**：档位上限集中在 `perf/profiles.json`（`real` / `gate`），`evaluatePerf` 两档共用：renderer ready 峰值、app 总峰值、末轮 settle renderer 上限（`settleRendererBytes`：real 1,363,148,800 B / gate 1,073,741,824 B）、第 3 轮相对第 2 轮增量 `Δ3 ≤ min(100 MiB, max(30% × Δ1, 25 MiB))`（仅 `upsert` 生效）。生效阈值写入 `verdict.appliedThresholds.appliedRoundDeltaBytes`；违规 id 集合固定 `renderer-peak` / `renderer-round-peak` / `renderer-settle` / `settle-missing` / `app-total-peak` / `round-delta` / `hold-comparisons` / `hold-row-models` / `hold-tabs` / `hold-unmeasured` / `invalid-sample` / `harness-error`，另有 `hot-round-hashed` / `hot-round-growth` / `settle-growth` / `reclaim-missing` / `reclaim-renderer` / `renderer-restart` 与非致命 `notices[]`（`renderer-peak-over-target` / `renderer-round-peak-over-target`）。阈值只许为覆盖真实持有而新增 / 收紧，不得为变绿放宽。
- **多 tab 持有形态：瞬峰护栏 vs 用户可见硬线**：多 tab 场景（`multisession` / `retained`）的瞬时 ready 峰值只作回归护栏 `TRANSIENT_PEAK_GUARDRAIL_BYTES = 2_415_919_104`（2.25 GiB），超 profile 目标但未越护栏只写 `notices[]`、不判红；`settle` / `settleStages`（阶段间抬升 ≤ 100 MiB）/ `appTotal` / `reclaim`（≤ `RECLAIM_RENDERER_BYTES = 1_153_433_600`，关 1 tab 后 `tabs = pairs − 1`）/ 热轮 `hashedFiles = 0` / `hold` 结构（`comparisons` = 场景 tabs、`tabs` 按同一份 `expectedHoldTabs`）仍是硬线。`upsert` 的 profile 峰值硬线不变，`perf/profiles.json` 六项数值零改动。
- **退出码**：带 `--fail-on-violation` 且违规时非零退出，证据仍完整写出；`invalid-sample` 无论是否带该开关都非零退出。
- **证据文件（`src/shared/perf/types.ts` + `src/main/perf/evidenceFile.ts`）**：单个 JSON（`schema: opencompare.perf.directory/v1`，只做加法扩展），**原子写**（同目录临时文件 + `rename`），单次 < 5 MB。字段：`generatedAt` / `appPid` / `commit{sha,dirty}` / `mode` / `pairs[]` / `roots{left,right}` / `profile` / `sampling{intervalMs,settleMs}` / `memoryDefinition` / `counts{files,dirs,hashedFiles,bytesToHash}` / `rounds[{index,startedAt,endedAt,wallMs,sessionId,tabs,counts,rendererRss,roundPeak,appTotalRss,rendererPid}]` / `totalWallMs` / `env{os,arch,cpuModel,cpuCount,totalMemBytes,node,electron}`（运行期真实探针）/ `samples[{label,phase,round,at,rss,pids}]` / `peaks{renderer,main,appTotal}` / `settle` / `settleAt` / `holds[]` / `settleStages[{label,rss,at,tabs}]` / `reclaim{tabs,rss,at}` / `roundDeltas[]` / `verdict{ok,violations[],appliedThresholds,notices?}` / 失败时的 `error`。运行失败（崩溃 / 提前关窗 / 超时）仍写带 `error` 与 `verdict.ok=false` 的部分证据并退出非零。
- **门禁命令（`pnpm perf:gate`，`scripts/perf-gate.mjs`）**：在系统临时目录生成**真实落盘**数据集（每侧 6,000 文件、内容 ≥100 MiB、`d0/…/d4` 五层、每 50 文件一处同大小不同内容、左右各含指向文件 / 目录 / 悬空目标的符号链接，另造 `links/left` 目录符号链接作第三对根），同一数据集跑**三次** harness（`gate` 档、`--settle 5000`、超时 300 s）：① `upsert` 1 对根 5 轮——tab 恒 1、`sessionId` 恒定、每轮 hold `comparisons=1` / `rowModels≤2` / `gc=true`、第 1 轮 `hashedFiles>0` 且第 2–5 轮为 0；② `multisession` 3 对根各 1 轮——tab 1/2/3、每轮 `comparisons = tabs`、`rowModels≤2`、第 3 轮（别名轮）`hashedFiles=0`、逐轮峰值 ≤2.25 GiB 护栏、`peaks.appTotal` ≤2 GiB；③ `retained` 3 对根 + 2 轮热 upsert——tabs `1/2/3/3/3`、hold 序列 tabs 与 comparisons 均为 `1/2/3/3/3/3/3/2`、热轮 `hashedFiles=0`、两条 `settleStages` tabs=3 且抬升 ≤100 MiB、`reclaim.tabs=2` 且 renderer ≤1,100 MiB、`appTotal` ≤2 GiB、`rendererPid` 唯一。三份证据都要求「周期采样条数 ≥ floor(wallMs/interval)−1」「`roots` 指向本次临时目录」「非样本路径」。违规即非零退出并输出被违反的阈值 / 结构 id。该命令只在条件 profile `.munk/code-gates.perf.json` 以单一 argv `pnpm perf:gate` 登记（默认矩阵不含），`RUN_TIMEOUT_MS = 300_000`，运行结束清理数据集；`PERF_GATE_EVIDENCE_DIR` 只额外复制证据，不改判定与退出码。
- **文档与真实取证（`docs/perf/`）**：`docs/perf/large-directory-memory.md` 给出 DawnChat↔ZenMind 的可复制命令（含 `--mode` / `--settle`）、产物路径、证据字段与口径、三种持有模式、结构断言、两档阈值与判定规则，并把 **ready 峰值** 与 **+settle 静置** 分列；§5 写死历史盲区（旧 harness「每轮释放会话 + 不渲染视图」不等于真实 UI 持有）与修复（视图 key 释放）及实测数字；`docs/perf/evidence/` 保存真实两目录实跑证据，不提交生成的数据集。
- **公开发布包只读诊断（`docs/perf/upsert-memory-diagnosis-2026-10-23.md`）**：对已发布公开包（dmg sha256 锁定）用 CDP 驱动真实 UI 路径只读测量（同会话 upsert 5 轮 / 干净启动 3 会话），复用只读原脚本（运行前后 sha256 不变），逐轮字段由同一实例上的只读侧采样器补齐（1 s 轮询 `Memory.getDOMCounters` / `performance.memory.usedJSHeapSize,jsHeapSizeLimit` / renderer 内 `ComparisonCache.stats` 的 `misses` 增量）；ready 峰值与 +20 s 静置收敛值**必须分列**；仓库外留 ≥3 份 `*.heapsnapshot`（快照前 used / 快照后 live 差值）并回答 ready 时上一轮 `DirectoryComparison.root`、`DirectoryRowModel`、`Cache.hashes` 是否仍可达；诊断产物只写一份仓库文档，`src/` / `package.json` / 门禁 / 发布文件一律不动。

## 验收

- **ac-single-command-evidence**：给定两个可读真实目录与 `--rounds N --out <file>`，一条命令跑完 N 轮并以退出码 0 写出可被 schema 读取的证据，`rounds.length === N`。
- **ac-cli-validation**：缺必填 / 未知参数 / 非法 mode / 左右数量不一致 / 模式与根对数不符 / `--rounds` 非正 / `--settle` 为负或超限 / 根不存在时非零退出，stderr 指明违规项，且不留标记成功的证据；旧命令行（不带 `--mode` / `--settle`）仍解析为 `upsert` / 20000 ms。
- **ac-evidence-schema / ac-env-probes-real**：证据含全部必填字段与类型（含 `holds` / `settleStages` / `reclaim` / `roundDeltas` / `verdict.appliedThresholds`），`peaks` 不含 settle；`env` 与运行期真实探针一致（`os` / `cpus` / `totalmem` / node / electron），不是常量。
- **ac-sample-points / ac-app-total-rss**：每轮至少 pre / post 各 1 条、边界成对、周期采样条数 ≥ `floor(wallMs/interval)−1`、末轮有 settle 且时长等于 `--settle`；`appTotal` = 所有进程 `workingSetSize` 之和，`renderer` 取 Tab 最大者，`main` 为 Browser；聚合函数有单测，口径字符串写入 `memoryDefinition`。
- **ac-same-process-rounds**：所有轮次在同一应用实例完成，`appPid` 唯一且各轮 renderer pid 相同。
- **ac-harness-hold-modes / ac-harness-no-release**：`upsert` 每轮复用同一 `sessionId`（tab 恒 1）、`multisession` 逐轮追加 1→2→3、`retained` 建 3 tab 后按 `--hot-rounds` 热 upsert 并关活动 tab 落到相邻已驻留 tab；证据记录 `mode` / `pairs` / `rounds[].tabs` / `settleStages` / `reclaim`；源码与证据双证「轮界不释放旧会话」。
- **ac-structural-single-hold**：`upsert` 5 轮后 `holds` 为 `comparisons=1` / `rowModels≤2` / `tabs=1`；`multisession` / `retained` 每轮 `comparisons` 等于当轮 tabs、`rowModels≤2`；3 tab 只剩 1 份 comparison 判 `hold-comparisons` 红；`gc=false` 或 holds 缺失记 `hold-unmeasured` 红。
- **ac-gate-red-on-old-behavior / ac-gate-red-on-violation**：旧行为（轮界释放 / 保留旧引用 / 无视图 key / 摘要化）下门禁必须失败，交付给出可复现命令或单测用例；给一份超峰值 / settle / 结构计数的证据，判定路径返回 `ok=false` 且非零，输出列出违规 id。
- **ac-gate-covers-upsert-and-multisession / ac-perf-gate-three-modes**：单次 `pnpm perf:gate` 同时覆盖 upsert 5 轮、multisession 3 会话与 retained 3 tab + 2 轮热 upsert，三份证据 `verdict.ok=true` 并各给峰值、settle / settleStages / reclaim 与 holds 结构断言；违例时非零退出。
- **ac-real-ui-upsert-peak / ac-real-ui-upsert-settle / ac-real-ui-multisession / ac-real-ui-app-total / ac-real-ui-no-regression**：打包 app + 原样 CDP 脚本——同会话 upsert 5 轮逐轮 ready ≤1,610,612,736 B、+20 s 静置 ≤1,363,148,800 B（末轮再 +30 s 仍 ≤）、3 会话 3 tab ready ≤1,610,612,736 B 且静置 ≤1,363,148,800 B、任一轮 app 总 ≤2,684,354,560 B；四态仍为 `same 38542 / added 701232 / deleted 6827 / modified 5878`、tabCount / PID / `allRoundsReady` / `blockedAt` 符合预期。
- **ac-hot-wallclock-no-regression / ac-hash-accounting / ac-cache-untouched**：热轮（第 2–5 轮）墙钟 ≤12,000 ms 且 `hashedFiles=0`；`counts.hashedFiles` / `bytesToHash` 等于该轮真实 `digestFiles` 累计；`DEFAULT_COMPARISON_CACHE_MAX_BYTES` 仍 134217728、淘汰逻辑不变、`pnpm test:memory` 通过。
- **ac-verdict-rule / ac-fail-on-violation**：判定按档位计算（峰值 / settle / Δ3 与 `appliedThresholds`），结构断言失败即 `ok=false` 并列出违规 id；多 tab 瞬峰只在 >2.25 GiB 时判红、超 profile 目标只进 `notices[]`；带 `--fail-on-violation` 违规时非零且证据完整。
- **ac-gate-wired / ac-gate-real-dataset**：`perf-gate` 只在条件 profile 以单一 argv 登记（默认矩阵不含，形状归 `quality-gates`）；单次 ≤3 分钟；数据集在系统临时目录、运行结束清理，含 ≥5,000 文件 / ≥100 MB / ≥5 层 / 同大小不同内容 / 文件·目录·悬空链接 + 第三根，`roots` 指向真实临时目录、不含 `fixtures` 或 `/samples`。
- **ac-normal-start-unaffected / ac-no-product-semantics-change**：不带 perf 参数与 env 启动不采样、不写证据；四态语义、对比 / 合并算法、树结构、`.ocsnap.json` 线格式、tab 身份与顺序、下钻返回、同步 dry-run、进度与取消均不变。
- **ac-doc-real-command / ac-docs-dual-column / ac-real-evidence**：文档含可复制命令与产物路径、字段口径、两档阈值与判定规则，ready 峰值与 +20 s 静置**双列**并写明历史盲区；`docs/perf/evidence/` 有真实两目录证据（`roots` 非样本、`samples` 非空、`commit.sha` 与 HEAD 一致），未跑满时如实记录原因，禁止填充或估算。
- **ac-release-files-untouched / ac-readonly-scope**：`package.json#version`、CHANGELOG、README 版本表、release workflow / notes / 发布证据零改动，未 push / tag / 发版；采样与取证期间不改 `src/`、`package.json`、门禁、发布文件。
- **ac-sampling-isolation**：采样起止 ISO 时间、负载与 CPU 写入报告；窗口内无构建 / 测试 / 门禁 / 其它 QA 进程，检测到并发即作废重采；组间退出 app 并确认无残留，每组独立 `--user-data-dir` 与端口，同一 UD 不跨组复用。
- **ac-baseline-v026 / ac-original-scripts / ac-repeat-fields / ac-ready-settle-separated / ac-concurrent-3**：只认公开 v0.2.6 包（dmg sha256 逐字、版本 / 签名 / `app.asar` / tag→commit 复核，任一不符即停）；原脚本运行前后 sha256 一致；每轮字段非空、tab 与四态符合固定值；ready 与 +20 s 静置分列并按字节比较；3 tab 建齐证明无 upsert 折叠。
- **ac-heap-retainers / ac-hot-wallclock / ac-history-contrast / ac-report-single-deliverable**：仓库外 ≥3 份 heapsnapshot 有 used / live 与「结果树 / 行模型 / 缓存条目是否 held」结论（含 retainer path 或不可达证据）、明确 128 MiB 估算是否只覆盖哈希条目；热轮墙钟与基线对照；历史数字只作对照；诊断报告是唯一新增仓库文件且 10 个必填小节齐全，缺一不通过。
- **ac-group3-single-sampling / ac-group3-rounds-under-cap / ac-group3-tabs-and-hot / ac-group2-retained**：真实规模 3 tab 驻留只采 1 次（同 commit），逐轮 ready ≤1,610,612,736 B、静置 ≤1,363,148,800 B、app 总 ≤2,684,354,560 B；tabs 按场景恒定、热轮 `hashedFiles=0`、`cache.misses` / `entries` 不随轮次增长、四态固定、renderer PID 不变；3 tab 建齐不释放旧 tab，反向步仅 added / deleted 互换。
- **ac-honest-if-still-over / ac-delivery-report**：仍越线时如实给出越线轮次 / 越线量与剩余持有路径，不得以 harness 绿灯、缩缓存或降阈值代替达标；交付写清 commit / 单次采样命令 / 逐轮结果与基线对照，注明打包 app 的 CDP L3 由负责人另排。
- **ac-quality-gates**：`pnpm lint` / `typecheck` / `build` / `test` / `test:memory` 通过；采样通过（若红则如实交付红，不重跑试绿）。

## 非目标

- 不做任何内存优化：缓存上限 / 淘汰、会话释放、行模型懒构建一律归 `memory-bounded`；本域除测量所需最小统计钩子外不得改变缓存与持有行为。
- 不改符号链接口径（归 `symlink-semantics`）、取消行为与取消日志（归 `io-concurrency`）；测量入口不触发取消。
- 不做版本号 / CHANGELOG / README 已知问题翻转 / 发布说明 / 资产校验（归 `release`）；不改历史发布证据。

## 实现约束

- **入口形态单一**：复用现有 `electron-vite` 主 / 渲染构建；轮次编排在渲染进程，采样与证据落盘在主进程，两者经仅测量模式启用的受控通道同步；不另开第二套 harness。
- **harness 持有语义 = 真实 UI**：渲染真实 `SessionTabs` + `DirectoryView`，会话列表只用 `workbench/sessionStore.ts` 共享纯函数；不得存在「轮次开始前释放上一轮会话」的钩子，也不得用「每轮换 session id」规避 upsert 语义。
- **强制 GC 可失败不可跳过**：`--expose-gc` 只在 perf 模式安装；`gc` 不可用即 `hold-unmeasured` 红。
- **默认零行为变化**：仅 `--perf-harness` + `OPENCOMPARE_PERF=1` 同时存在才激活，判断可被单测断言。
- **RSS 必须真实**：来自 `app.getAppMetrics()` 的 `workingSetSize` / `peakWorkingSetSize`；禁止 JS heap 估算或 mock；缺失或 0 记 invalid 并非零退出。
- **哈希计数落在真实调用上**：允许在 `@core/directory` 增加可选统计回调，但不得改变对比结果、四态、`counts`、快照格式与既有测试语义。
- **阈值单点**：`src/shared/perf/verdict.ts` 单点实现、两档共用；上限集中在 `perf/profiles.json`，不在多处硬编码；新增 `settleRendererBytes` 与结构断言也走同一 `evaluatePerf`。
- **证据原子写**：临时文件 + `rename`；失败也写带 `error` 与 `verdict.ok=false` 的部分证据并非零退出；单次 < 5 MB，不提交数据集。
- **周期采样**默认 1 s、可覆盖（上限 2000 ms）并写入证据；门禁单次 ≤3 分钟、超时即红；不依赖本机 DawnChat / ZenMind 是否存在。
- **数字可追溯**：文档与证据任何数字可追溯到命令与原始输出；真实两目录取证与门禁小数据集是两件事，不得互相替代。
- **只读诊断的隔离与口径**：先确认无 `pnpm` / `electron-vite` / `vitest` / `perf:gate` / `test:memory` 在跑；采样窗口内不叠构建或门禁（要跑门禁须等采样结束并完全退出 app，或先跑门禁待机器空闲 ≥10 分钟）；每组单独 `--user-data-dir` 与端口；启动 `<app>/Contents/MacOS/OpenCompare --remote-debugging-port=<port> --user-data-dir=<ud>`，等 `/json/version` 可读再挂 CDP，版本以包与 UA 双证；RSS 走 `ps -axo rss=`，heap 走 `Performance.getMetrics().JSHeapUsedSize`，DOM 走 `Memory.getDOMCounters`，`hashedFiles` 走缓存 `misses` 增量；证据放仓库外固定目录，阈值按字节比较；报告中文、字节与 MiB 双列、结论可从同文证据复算。
